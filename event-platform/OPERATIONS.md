# ローカルスペース — 運用設計 v1

更新: 2026-08-27

## 原則

通常運用は可能な限り自動化する。運営者本人が必要なのは、法令上/本人確認上/物理的に人間しか実行できない作業と、最終的な例外判断に限定する。

## 自動化済み・自動化前提

- SPACE/WANT/EVENT投稿の形式・禁止語・権限確認チェック
- 求人/長期賃貸等の明確な対象外投稿の拒否
- WANT/EVENTの日付終了による自動期限切れ
- SPACEの180日未更新による更新待ち化
- 独立通報3件以上による自動非公開
- 分析イベントの180日超データ削除
- 都市別日次KPI集計
- 公開検索・客観スコア計算
- 画像縮小・形式変換・最大枚数/容量制限
- 掲載削除時の画像削除
- 旧課金経路の停止
- CIによる法務境界・API・静的ファイル監査

## 人間判断に残すべきもの

- 権利侵害の複雑な申立て
- 行政/警察/裁判所等からの正式な照会
- 投稿内容だけでは判断できない重大安全案件
- 新しい有料モデル・予約・成功報酬を導入する際の行政確認/専門家確認
- Cloudflare等のアカウントOAuth/KYCのように本人操作が必須な認証

## 営業

現在は営業メール送信・問い合わせフォーム送信を実行しない。営業用の資料・リスト設計・文面・KPI設計までは準備可能だが、送信操作は保留する。

## 日次監視

自動監視で確認するもの:
- API health
- GitHub開発プレビューがnoindexのままか
- 課金/予約/成功報酬コードが混入していないか
- 旧Stripeリンクがソースにないか
- CORS許可元
- API禁止境界E2E
- DB cronの稼働

## 週次運営レビュー（実証開始後）

都市別に最低限以下を見る:
- SPACE公開数 / 新規数
- WANT公開数 / 新規数
- EVENT公開数 / 新規数
- 掲載詳細閲覧数
- 外部問い合わせクリック数
- WANT→EVENT数
- 60点以上候補の不足率
- 通報・自動非公開件数

数値が悪い場合は、全国展開ではなく青森市の供給/需要獲得を先に修正する。
