# ローカルスペース — 事業戦略 v3（青森市実証 → 全国展開）

更新: 2026-08-27

## 一文で定義

**使われていない小さな場所と、「ここで何かやりたい」をつなぎ、決まった催しを地域イベントカレンダーへ変換する。青森市で1都市の勝ち方を実証し、成立した型を都市単位で全国へ複製する。**

## 事業の核は3面だけ

1. **SPACE** — 店先、軒先、空き地、駐車場の一部、店舗・施設の一部など、一時利用できる小さな場所。
2. **WANT** — ポップアップ、ライブ、展示、ワークショップ、物販等のため場所を探している企画。
3. **EVENT** — 開催が決まった小さな催しまで載せる地域イベントカレンダー。

初期版では出演者、広告会社、運営スタッフ等の別市場を足さない。まず「場所が見つかる」「小さい催しが見つかる」を成立させる。

## 青森市の位置付け

青森市は最終市場ではなく **Pilot City / PMF検証都市**。

検証するもの:
- まだオンライン化されていない小口SPACEを十分に集められるか。
- WANTが実際にSPACEへ問い合わせるか。
- 一度使った人が再利用するか。
- 開催決定したWANTがEVENTへ変換され、カレンダーが需要獲得装置になるか。
- 供給獲得・需要獲得・安全管理の手順を他都市へ再現できるか。

全国へ一気に薄く拡大しない。**都市内流動性を作ってから次都市へ進む。**

## 成長ループ

```text
SPACE掲載
  ↓
WANTが検索 / 客観スコアで候補発見
  ↓
掲載者の外部窓口で直接相談・合意
  ↓
WANT → EVENTへ変換
  ↓
地域カレンダー掲載 + 希望者は無料簡易SNS告知候補
  ↓
地域住民・新規主催者がサイトを発見
  ↓
新しいWANT / SPACEが増える
  ↓
同じ都市の流動性が高まる
```

## 初期差別化

大手レンタルスペースの正面コピーをしない。狙うのは、まだ「レンタルスペース商品」として整備されていないロングテール。

- 店先2〜3㎡
- 軒先
- 私有地の一角
- 駐車場1〜2台分
- 定休日だけ空く店舗
- 営業時間外の一角
- 少人数向け小スペース
- 数時間〜1日の小さな活動

加えて、供給一覧だけではなく **WANT（逆指名型の需要掲示）** を持ち、潜在供給を掘り起こす。

## 競争優位の作り方

長期的な防御力はサイト機能そのものではなく、次の4つに置く。

1. **都市ごとの供給密度** — 近所で本当に使える場所が多い。
2. **ロングテールEVENTデータ** — 他カレンダーに載らない小イベントが蓄積する。
3. **都市立ち上げプレイブック** — 何件のSPACE/WANTをどの順で集めれば流動性が生まれるかを実測で持つ。
4. **地域内フライホイール** — SPACE → WANT → EVENT → 閲覧者 → 新WANT/SPACE の循環。

## 顧客獲得戦略

### 供給側を先に作る

1都市の開始直後は供給不足が最も致命的。青森市では最初にSPACE密度を作る。

優先候補:
- 店先・軒先を持つ小売店
- 飲食店の休業時間帯や外部スペース
- ギャラリー・スタジオ
- 空き駐車場・私有地
- 小規模施設・コミュニティ施設
- 所有者・管理者が一時利用を許諾できる空き区画

訴求: **「空いている時間・場所を、まず無料で見つけてもらう」**。

### 需要側

- ハンドメイド作家
- 小規模物販
- ミュージシャン・表現者
- 学生団体
- ワークショップ主催者
- 個人事業者
- 移動販売等（個別許認可は各自確認）

価値は「場所検索」だけではなく、開催後にEVENT化して無料カレンダー掲載・希望者は簡易告知候補になること。

## PMF計測

登録者数やPVを北極星指標にしない。

### 北極星指標

**月間実利用成立数**

初期の情報提供型ではサイト内で契約成立を取得しないため、正式な成立計測機能を法務上安全に設計するまでは以下を先行指標として使う。

- SPACE公開数
- WANT公開数
- EVENT公開数
- SPACE詳細閲覧数
- 外部問い合わせクリック数
- WANT→EVENT変換数
- お気に入り数
- 1 WANTあたり高一致SPACE数
- 1 SPACEあたり高一致WANT数
- カレンダー閲覧セッション
- 再訪 / 再掲載（後続計測）

### 青森市の初期ゲート（事実ではなく経営判断用の暫定目標）

90〜180日で目指す第一ゲート:
- 公開SPACE: 100件
- 月間WANT: 30件以上
- 月間EVENT: 50件以上
- 月間WANT→EVENT: 10件以上
- WANTの50%以上に60点以上のSPACE候補が1件以上
- 外部問い合わせクリックが継続的に発生
- 重大な権利・安全事故: 0

この数値は市場実績ではない。実データが貯まったら更新する。

## 都市展開ゲート

次都市へ進む条件を「カレンダーPV」だけにしない。

最低限:
1. 供給100件規模を再現可能な手順で獲得できた。
2. WANTに対して候補が十分に出る。
3. 外部問い合わせが実際に発生する。
4. WANT→EVENT変換が継続する。
5. 再利用者が出る。
6. 通報・権限問題を運用可能な水準で管理できる。

## 全国展開順序

```text
青森市
 ↓ PMF
近接 / 類似地方都市 3〜5都市
 ↓ 再現性確認
10〜30都市
 ↓ 都市立ち上げ標準化
50〜150都市
 ↓ ブランド・データ・SEO/カレンダー網
全国主要都市
```

「全国1,000件」より「各都市100件」を優先する。

## 収益化の順序

### Phase 0 — 無料流動性
- SPACE/WANT/EVENT掲載無料
- 検索・客観マッチ無料
- 地域カレンダー無料
- 簡易SNS告知は希望制・無料・効果保証なし

### Phase 1 — 取引非連動の収益
法務境界を維持しやすい固定対価を先に検討。
- EVENT注目枠
- 特集掲載
- SNS告知クリエイティブ制作
- 広告運用代行
- 法人向け固定掲載プラン

料金は契約成立額と切り離す。

### Phase 2 — 予約 / 成功報酬
本来構想の「場所代の○%」は、事業固有の行政確認または必要な免許・提携体制の確定後にのみ有効化する。

## ユニットエコノミクスの考え方

将来の成功報酬率を今固定しない。決める前に以下を実測する。
- 1取引あたり平均場所利用額
- 支払決済費
- CAC
- サポート時間
- キャンセル / 返金率
- 不正・紛争率
- リピート率

超小額取引では率だけでは採算が薄くなり得るため、法的に実装可能と確認された場合でも「率 + 最低手数料」等を実データで検討する。

## 全国展開可能なシステム設計

- 都道府県 / 市区町村 / 詳細エリアを分離保存。
- 都市ごとの日次KPIを集計。
- 公開一覧APIをページング。
- 画像は最大3枚、公開権限確認必須。
- 第三者広告トラッカーを使わず、匿名セッションをハッシュ化した第一者計測。
- 分析イベントは原則180日保持。
- SPACE/WANTの候補スコア理由を表示。
- 求人、長期賃貸、権限のない公共空間をサーバー側で拒否。

## 初期にやらないこと

- 全国同時ローンチ
- 求人・職業紹介
- 出演者 / 広告会社 / スタッフの別マーケット
- サイト内DM
- サイト内予約
- 利用者間決済
- 成約成功報酬
- 場所契約の代理・交渉

**青森市で「都市内の小さな場所と小さな催しが循環する」ことを実証する。それが成立したら、その運営方程式を全国へコピーする。**
